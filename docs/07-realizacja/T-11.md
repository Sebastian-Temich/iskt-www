# Raport T-11: Formularz kontaktowy end-to-end - walidacja, endpoint, Resend, rate limit

Issue: #11
PR: #NR_PR

## Co zrobiono

- **Schemat `src/lib/contact-schema.ts`** (Zod, wspólny dla formularza i endpointu): imię 1–100,
  e-mail w formacie i ≤ 254, wiadomość 1–5000 znaków liczonych w code points (`codePointLength`),
  bez CR/LF w imieniu i e-mailu, honeypot `website` pusty (`z.literal('')`), `isHoneypotFilled`
  dla endpointu, `validateContact` zwraca pierwszy komunikat na pole. Testy:
  `src/lib/__tests__/contact-schema.test.ts` (wartości poprawne, puste, za długie, CR/LF, format
  e-mail, maksymalne długości ze znaków 4-bajtowych, e-mail dokładnie 254 znaki).
- **Endpoint `src/pages/api/contact.ts`** (`prerender = false`, `POST` i `ALL`): 405 dla metod innych
  niż POST (z `Allow: POST`), `Origin` ≠ `PUBLIC_SITE_URL` → 403, typ inny niż `application/json`
  (charset tylko UTF-8) → 415, rate limit → 429, ciało > 32 kB (deklarowane `Content-Length` albo
  liczone przy czytaniu strumienia) → 413, zły JSON/UTF-8/pola → 400 `{error:"invalid", fields}`,
  honeypot → 200 bez wysyłki, błąd lub timeout Resend → 502 `{error:"send_failed"}`, sukces → 200
  `{ok:true}`; `Cache-Control: no-store`. Logika w `createContactHandler` z wstrzykiwanymi zależnościami.
  Testy: `src/lib/__tests__/contact-endpoint.test.ts` z mockiem mailera dla każdego kodu, w tym JSON
  maksymalnej długości ze znaków 4-bajtowych → 200 (ok. 20,7 kB) i ciało dokładnie 32 kB (nie 413).
- **Mailer `src/lib/mailer.ts`**: Resend SDK (ładowany dynamicznie), wyłącznie `text`, `from` =
  `CONTACT_FROM`, `to` = `CONTACT_TO`, `replyTo` = e-mail nadawcy, temat `[iskt.pl] Zapytanie z
  formularza: IMIĘ`, `AbortController` 10 s (sygnał przekazany do SDK i wyścig z timerem),
  `idempotencyKey` z `requestId`, `MAIL_TRANSPORT=mock` loguje tylko zdarzenie. Testy:
  `src/lib/__tests__/mailer.test.ts` (treść bez HTML, adresy, błąd API, wyjątek, timeout 10 s z
  fałszywymi zegarami, abort, mock).
- **Rate limit `src/lib/rate-limit.ts`**: `check(ip)`; `waf` → noop, `upstash` → `@upstash/ratelimit`
  okno przesuwne 5/600 s, klucz SHA-256(IP + sól), `memory` tylko do testów (odrzucany przy
  `PUBLIC_SITE_ENV=production`). Testy: `src/lib/__tests__/rate-limit.test.ts` (6. żądanie → odmowa,
  okno przesuwne, upstash z mockiem i bez surowego IP w kluczu, brak zmiennych Upstash → `EnvError`).
- **Logi `src/lib/log.ts`**: zapisuje wyłącznie `event`, `status`, `code`, `requestId` (inne pola są
  odrzucane). Test `src/lib/__tests__/log.test.ts` przepuszcza przez endpoint ścieżki sukcesu, 400,
  honeypot, 403, 415, 413, 502, 429 i awarię limitera i sprawdza, że żadna linia nie zawiera imienia,
  e-maila, treści ani IP.
- **ContactForm** (`src/components/home/ContactForm.astro`, `src/components/ui/Field.astro`): wysyłka
  `fetch` JSON na `/api/contact/`, przycisk `disabled` + `aria-busy` w trakcie i blokada drugiego
  `submit`, stan sukcesu „Dziękujemy!” z designu (fokus na nagłówku), błędy przy polach
  (`aria-invalid`, `aria-describedby` → `field-NAME-error`) z fokusem na pierwszym błędnym polu (walidacja
  w przeglądarce tym samym schematem i błędy 400 z serwera), komunikat błędu wysyłki/sieci i 429 w
  `role="alert"` z zachowaniem wpisanych danych, honeypot poza ekranem (`tabindex=-1`,
  `autocomplete=off`, `aria-hidden`), robocza klauzula informacyjna pod przyciskiem z linkiem
  `/polityka-prywatnosci/`. Bez JS formularz ukryty, `<noscript>` z `mailto:biuro@iskt.pl` i telefonem.
  Testy: `e2e/contact.spec.ts` (chromium + webkit, `MAIL_TRANSPORT=mock`, także `javaScriptEnabled:
  false`, oraz bezpośrednie żądania do endpointu: 200, honeypot, 400, 403, 405, 413, 415).
- **Spike ADR-003:** wyniku na stagingu/preview nie ma. Worker nie ma dostępu do panelu Vercel ani
  adresu stagingu z regułą WAF, więc nie mógł sprawdzić „6. POST z jednego IP w 10 min → 429”.
  Opis w „Ryzykach”: brak potwierdzonej reguły WAF zostaje do decyzji właściciela.
- **`.env.example`:** nie zaktualizowany, bo profil workera blokuje edycję `.env*`. Eskalacja E-004,
  brakujący blok jest w „Ryzykach”.
- **Lint, typy, testy, gitleaks:** zielone lokalnie (sekcja „Testy”).

## Decyzje

- Jak uruchomić E2E z endpointem, skoro `@astrojs/vercel` nie obsługuje `astro preview` dla buildu z
  `prerender = false`? → `astro.config.mjs` wybiera `@astrojs/node` (devDependency) przy
  `ASTRO_ADAPTER=node`, a `playwright.config.ts` ustawia tę zmienną w `webServer.env`; Vercel i
  wszystkie inne buildy używają adaptera Vercel. Pliki spoza „Zakresu”: `astro.config.mjs`,
  `playwright.config.ts`, `package.json`, `pnpm-lock.yaml`.
- Jak zachować `/404/` w E2E z serwerem Node? → integracja `iskt:e2e-node-preview` (tylko przy
  `ASTRO_ADAPTER=node`) kopiuje `404.html` do `404/index.html`, tak jak serwował statyczny preview.
- Jak sprawdzić nagłówek `X-Robots-Tag` i build produkcyjny po przejściu na build serwerowy? →
  `e2e/seo.spec.ts` (plik spoza „Zakresu”) robi osobne buildy z adapterem Vercel (staging i produkcja,
  helper `vercelBuild`), czyta pliki z `.vercel/output/static`, bo przy buildzie serwerowym strony
  lądują w `outDir/client/`, i przywraca `.vercel/output`.
- Jaki `Origin` przyjmuje endpoint w E2E? → `PUBLIC_SITE_URL` = adres serwera testów
  (`http://localhost:55327`) w `webServer.env`.
- Adres endpointu? → `/api/contact/` z końcowym ukośnikiem (`trailingSlash: 'always'`); bez ukośnika
  Vercel odpowiada 308, a w preview Node żądanie nie dociera do `POST` (405).
- Jaki kod dla złego `Origin`? → 403 `{error:"forbidden"}` (issue nie podaje kodu). Typy formularzowe
  z obcym Origin odrzuca wcześniej wbudowany `security.checkOrigin` Astro (403), w pozostałych
  przypadkach endpoint daje 415.
- Kolejność sprawdzeń? → metoda, Origin, typ, rate limit, rozmiar, JSON, honeypot, walidacja,
  wysyłka. Rate limit przed czytaniem ciała, więc liczy też boty; honeypot przed walidacją, żeby boty
  nie dostawały sygnału o błędnych polach.
- Co przy awarii magazynu limitu (Upstash)? → przepuszczamy zgłoszenie i logujemy
  `rate_limit_unavailable` (W-04 ma pierwszeństwo, a w wariancie `waf` limit i tak działa przed funkcją).
- Co przy błędnej konfiguracji serwera (`EnvError`)? → 500 `{error:"server_error"}`, log
  `contact_config_error` bez nazw i wartości zmiennych.
- Zmienne Upstash? → `UPSTASH_REDIS_REST_URL` i `UPSTASH_REDIS_REST_TOKEN`, sprawdzane w
  `createRateLimiter` tylko przy `upstash` (bez zmiany istniejących testów `env.test.ts`).
- Upstash przez SDK czy REST? → `@upstash/ratelimit` + `@upstash/redis` zgodnie z ADR-003, ładowane
  dynamicznie tylko w wariancie `upstash`.
- Sekret wklejany do paczki funkcji → `runtimeEnv` przeniesiony do nowego `src/lib/runtime-env.ts`
  (plik spoza „Zakresu”), `env.ts` go reeksportuje. Wtyczka env Astro przy odwołaniu do całego
  `import.meta.env` wkleja wartości z plików `.env*` dla kluczy, których nazwy są w tekście modułu;
  stary `runtimeEnv` w `env.ts` (z nazwami zmiennych) wklejał klucz z `.env.local` do
  `.vercel/output/_functions`. Test regresji `src/lib/__tests__/runtime-env.test.ts`.
- `maxlength` w polach? → nie, bo liczy jednostki UTF-16 i ucinałby 100 emoji do 50; limity pilnuje
  schemat (code points).
- Formularz po sukcesie? → ukryty bez resetu (stan sukcesu z designu); wpisane dane zostają w DOM, co
  utrzymuje test M1 `e2e/home.spec.ts` (wartość pola po wysłaniu).
- Treść klauzuli? → robocza, zgodna z polityką prywatności (administrator, cel, link), do akceptacji
  przy odbiorze (P2).
- Dodatkowo przeczytane źródła: `e2e/home.spec.ts`, `e2e/layout.spec.ts`, `e2e/seo.spec.ts`,
  `e2e/qa/M1-scenariusze.spec.ts`, `src/pages/404.astro`, `src/content/site.ts`, `vercel.json`,
  `.github/workflows/ci.yml`, kod `astro` (preview, checkOrigin, wtyczka env) i typy `resend`.

## Ryzyka

- **Brak potwierdzonej reguły WAF (spike ADR-003) — do decyzji właściciela.** Worker nie miał dostępu
  do Vercel, więc nie sprawdził na stagingu/preview, czy 6. `POST` z jednego IP w 10 min daje 429.
  Domyślny `RATE_LIMIT_PROVIDER=waf` oznacza w kodzie brak limitu: bez reguły Vercel Firewall
  formularz nie spełnia W-05. Reguła musi obejmować ścieżkę **`/api/contact/`** (z ukośnikiem;
  najlepiej prefiks `/api/contact`), metodę POST, 5 / 600 s, akcja 429. Gdy plan Vercel jej nie daje:
  fallback `upstash` (konto Upstash, `RATE_LIMIT_SALT`, `UPSTASH_REDIS_REST_URL`,
  `UPSTASH_REDIS_REST_TOKEN`). Sprawdzenie: QA M2 na stagingu.
- **`.env.example` niekompletne (E-004).** Profil workera blokuje edycję `.env*`. Do dopisania pod
  sekcją rate limitu, bez wartości:

  ```
  # Upstash Redis REST (tylko przy RATE_LIMIT_PROVIDER=upstash, fallback ADR-003)
  UPSTASH_REDIS_REST_URL=
  UPSTASH_REDIS_REST_TOKEN=

  # Tylko build E2E (playwright.config.ts): node = adapter Node dla astro preview. Na Vercel nie ustawiać.
  ASTRO_ADAPTER=
  ```

  Opcjonalnie w komentarzu `RATE_LIMIT_PROVIDER`: „memory tylko w testach”.
- Brak testu prawdziwej wysyłki Resend (klucz testowy) i podglądu Vercel; endpoint w funkcji Vercel
  nie był uruchomiony, tylko build i serwer Node w E2E. Ręczny test na stagingu w QA M2.
- `pnpm dev` z `.env.local` (prawdziwy klucz testowy) nie był sprawdzony ręcznie; `runtimeEnv` w dev
  czyta pliki env przez obiekt zmiennych Vite, jak wcześniej.
- `vercel.json` nie ma jeszcze CSP (QA-M1-2); skrypt formularza to moduł Astro (plik zewnętrzny albo
  inline), co trzeba uwzględnić przy CSP.

## Propozycje dla systemu

- Profil workera: zezwolić na Edit/Write `.env.example` (skill sh-worker wymienia go w „Wyjściu”, a
  profil blokuje wszystkie `.env*`), zostawiając blokadę `.env`, `.env.local` i `.env.prod*`.
- Profil workera: zezwolić na prefiks zmiennych środowiskowych (`VAR=x pnpm …`) przy `pnpm`, żeby dało
  się uruchomić serwer podglądu z inną konfiguracją do debugowania, bez obchodzenia przez testy.
- Szablon zadania spike'a: gdy kryterium wymaga stagingu/panelu Vercel, issue powinno podać adres
  preview i stan reguły albo przypisać sprawdzenie do QA/właściciela.
